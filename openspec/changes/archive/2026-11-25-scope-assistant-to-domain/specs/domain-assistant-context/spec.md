# Spec Delta

## Purpose

助手与「当前域」的绑定契约：一个会话的助手能力必须以它在该域的身份为界，而不是以平台管理员身份为界；解析不到域时必须关闭而不是退化成无域助手。

## ADDED Requirements

### Requirement: 助手以当前域为上下文

助手 SHALL 以请求所在的域作为会话上下文，并 SHALL 让模型能看到该域的身份与该域当前的下一步动作。

**范围声明（按实施取证收窄）**：工具面中**只有 `search_clauses` 接受 `domain` 参数**；
`clause_*` / `rubric_*` / `contract_*` 等按 `contract_type` / `category` / `tags` 过滤，
不接受域。因此本版**不声称**工具面级别的跨域隔离——它做不到。跨域隔离由
「工具面不暴露域选择 + 提示词声明只在本域工作」约束，属**协作式**边界，不是强制边界。
把工具面真正按域隔离是 MCP 包层级的改动，记在 tasks §8.6。

#### Scenario: 域成员问本域的事

- **WHEN** 某域 expert 在该域页面打开助手并提问
- **THEN** 助手回答时使用该域的名称与角色，且能引用该域当前的可执行动作

#### Scenario: 提示词声明本域边界

- **WHEN** 助手收到任何提问
- **THEN** 注入的指令里含「你正在〈域名〉工作、只在本域范围内回答」这一句，且该句随请求而变化（不是进程启动时的常量）

### Requirement: 角色决定能力面

助手向模型暴露的能力面 SHALL 由该会话在当前域的角色决定：只读角色不得获得任何写能力，可写角色不得获得发布或升格能力，只有负责人角色可获得发布与升格能力。删除类能力 SHALL 对所有角色一律不可用。

#### Scenario: 只读角色没有写能力

- **WHEN** 一个 annotator 角色的成员让助手修改某条内容
- **THEN** 助手不做修改，并说明该操作需要更高角色

#### Scenario: 可写角色不能发布

- **WHEN** 一个 expert 角色让助手发布该域的一个版本
- **THEN** 助手不执行发布，并说明发布属于负责人

#### Scenario: 删除对任何角色都不可用

- **WHEN** 任何角色的成员（含平台管理员）让助手删除某条内容
- **THEN** 不发生任何删除，助手说明删除只能在工作台页面进行

### Requirement: 无可用域时 fail closed

当会话无法解析出任何可访问的域时，助手 SHALL 不可用：不得渲染入口、不得接受请求、不得以「无域上下文」的形态继续工作。

#### Scenario: 零域身份看不到助手

- **WHEN** 一个没有加入任何域的已登录用户打开工作台页面
- **THEN** 页面不含助手入口，其聊天端点对该会话返回拒绝

#### Scenario: 域解析失败不是无域降级

- **WHEN** 代理无法确定请求属于哪个域（缺失、未知或已归档）
- **THEN** 助手请求被拒绝并给出可分辨的原因，而不是以一个没有域的助手继续服务

### Requirement: 域边界在代理处执行

域与角色的判定 SHALL 由工作台侧的代理完成，运行时服务 MUST NOT 被作为绕过该判定的替代入口。

#### Scenario: 直连运行时不能越域

- **WHEN** 有会话绕过工作台代理直接访问运行时服务
- **THEN** 该路径不可达（运行时不是公开入口）
